Folio — Kindle private cloud architecture

A privacy-preserving, self-hosted library for jailbroken Kindles. Live at YOUR_HOST; source in the repo. The design deliberately does not impersonate Amazon's backend: a private server publishes a per-device manifest and book files; a device-side daemon downloads them into /mnt/us/documents/PrivateCloud, where the stock scanner indexes them into the normal Library UI. Reading progress, highlights and storage management ride the same device-initiated channel.

Server data model

  • books — one row per logical work (public_id is the external id everywhere).
  • book_files — one row per format; source ∈ upload/converted/scan. Scan rows reference files in place (read-only mounts, e.g. the Komga library). Carries the prepared delivery copy columns (prepared_path/sha256/size/at/source_sha256) and the cached EXTH identity (asin, cde_type).
  • devices — token-authenticated Kindles; telemetry columns (free/total bytes, battery, firmware, serial, kindled version) plus storage policy (low_space_threshold_mb, auto_evict).
  • deliveries — the per-device send queue and lifecycle: created (queued) → delivered_at (device downloaded) → optional evict_requested_at → removed_at (device deleted + acked). Re-sending reactivates the row.
  • reading_states — one .sdr bundle per book+device; parsed best-effort into progress_percent/last_position (MBP) with content_mtime as the reliable recency signal.
  • device_syncs — one row per daemon pass (downloaded/removed/pushed/applied/errors, duration, free bytes) for the device-page history.
  • annotations — highlights/notes/bookmarks parsed from My Clippings.txt, deduped by SHA-256 fingerprint per device, matched to books by title + author word-set.

Device API (manifest v3)

All endpoints under /api/v1, authenticated by the per-device X-Api-Token. The daemon is the only client; the contract is additive so old daemons keep working.

GET  /manifest                      → { version: 3, items: [...], removals: [...],
                                        status_url, clippings_url }
GET  /books/:id/file?fmt=…          → book bytes (delivered_at stamped)
GET  /books/:id/thumbnail           → cover JPEG (EBOK fallback path)
GET  /books/:id/reading_state       → newest .sdr bundle (tar.gz)
PUT  /books/:id/reading_state       → upload bundle (X-Sdr-Mtime)
POST /device/status                 → telemetry + sync report + on-disk book list
POST /removals/:delivery_id/ack     → closes an eviction
PUT  /clippings                     → whole My Clippings.txt

Manifest items[] serve the prepared file's sha/size/filename (see delivery preparation); removals[] list evict-requested deliveries with an ack URL. The status POST reconciles reality: books the daemon no longer has are closed out (removed_at, reason "missing on device"), pending deliveries found on disk get their delivered_at backfilled.

Daemon sync pass

  1. Fetch manifest.
  2. Per item: download when new/changed/missing (stream to .part, SHA-256 verify, atomic rename). Replacements delete the old file and let the scanner drop the row before the new bytes land — verified on 5.19.2 that in-place overwrites keep stale catalog metadata. Renamed deliverables (container changes) remove the old file; same-stem renames share the .sdr so position survives.
  3. Reading state: newest content mtime wins across devices; local sidecars are backed up before overwrite; restored files get the server mtime pinned so they never bounce back.
  4. Removals: push newer reading state first, delete book + sidecar + any installed thumbnail, drop the catalog row, ack.
  5. Upload My Clippings.txt when its mtime moved.
  6. POST device status (statvfs of the documents volume, battery via powerd battLevel, firmware, serial, pass report, on-disk book list).

Delivery preparation (the cover fix)

Every queued book is served from a prepared copy built by Library::KindlePrep. See the companion artifact Kindle 5.19 cover tiles: the three conditions for the on-device evidence. In short: ASIN EXTH records neutralized, cdeType rewritten EBOK→PDOC in every MOBI header, and KF8-only AZW3 transcoded to a joint MOBI6+KF8 container (--mobi-file-type both) because the 5.19 Library UI only renders cover art for MOBI6 containers. Covers are embedded via ebook-meta when the source lacks one. Preparation is queued on delivery, on conversion completion, and self-heals from the manifest (raw file serves until the prep lands; the sha change re-delivers).

Storage management

Each device reports storage every sync. When projected free space (after the pending queue lands) drops under the device's threshold, Library::EvictionPlanner proposes removals in order: finished (progress ≥ 95%), never opened (delivered ≥ 7 days), dormant (untouched ≥ 45 days) — sized to clear the shortfall, never touching recently-active books. Suggestions surface on the device page (one-tap "remove all"); with auto_evict the status endpoint applies the plan automatically. Removals ride the manifest and the row survives as history.

Web UI

  • Phone-first PWA; bottom nav scrolls horizontally on narrow screens.
  • Live updates via Turbo 8 morph refreshes over solid_cable — Delivery/Device/DeviceSync/Conversion/BookFile/ReadingState broadcast; the queue page, device pages, book pages and reading feed update in place.
  • Search: default mode matches titles/authors/series (FTS5 column filter); "full text" adds descriptions + Calibre-extracted text with snippets; "meaning" uses bge-small embeddings over sqlite-vec.
  • Book page facts link to filtered library views: author, series, language, publication year, added-date, per-format stamps.
  • "Keep reading" shelf (recent reading states < 96%), per-device progress bars, highlights & notes section, /notes browser.

Deployment

Docker via the traefik stack (your reverse-proxy compose file, service folio, build context server/). Solid Queue runs inside Puma. Storage under /var/lib/folio/storage; the Komga library is mounted read-only at /komga and referenced in place. Deploy = docker compose build folio && docker compose up -d folio; the entrypoint runs db:prepare. The daemon cross-builds with kindled/build-kindle.sh (rust-musl-cross docker image) and installs to /mnt/us/privatecloud/kindled; an upstart job (kindled/upstart/kindled.conf) starts it at boot and respawns it on crash.
