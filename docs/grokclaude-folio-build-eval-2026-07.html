grokclaude on a real Folio build — run eval, July 2026

The fonts / per-user prefs / preferred-Kindles ship (commit 83c91a0, 2026-07-29), reconstructed from the .grokclaude/ job artifacts, with the verdict on defaulting the workflow.

What was built, and how

The task: five selectable reading fonts in the Folio web reader, per-user reading settings synced server-side, a per-user /reading page with web-reading stats merged into keep-reading, and shared Kindles with a main user + per-user preferred device. All four features shipped in a single commit, 83c91a0 (“Add reader fonts, synced prefs, per-user reading page, and preferred Kindles”), verified green: 746 RSpec examples, 0 failures; RuboCop clean. Details of what shipped are in the commit message and the roadmap doc; this artifact is about how it was built.

The pipeline was the /grokclaude offload skill, its second feature-build outing: four parallel research jobs mapped the device model, writeback path, reader settings, and roadmap constraints into distilled reports; one build job (grok-4.5-build, in a managed gc/* worktree) implemented all four features with specs from a self-contained brief; the host (Claude) reviewed the worktree diff, fixed four defects, fetched the actual font files, and committed. Grok never committed — by design the builder sandbox denies .git writes.

What host review caught — and why it stays mandatory

Grok delivered complete, spec-covered, green-in-worktree code. Review still found four real defects before commit:

Load-bearing A green suite and a clean linter in the worktree did not mean shippable. The deploy-breaking defect was invisible to the worker's own verification because the worktree DB had already been migrated incrementally — only a fresh db:prepare (what production runs) would have hit it. Host review of the actual diff is not a formality in this pipeline; it is the step that makes the output committable.

Review also completed work grok scoped out: the builder shipped the font scaffold with silent fallback (“woff2s intentionally absent”), so the host fetched and committed the five families (Literata, Bitter, EB Garamond, Atkinson Hyperlegible, OpenDyslexic) with their OFL licenses. Asset acquisition either belongs in the brief explicitly or stays host-side.

Friction found this run

  • Worktree environment provisioning. The builder burned several of its 37 turns discovering that the gc worktree had no vendor/bundle, then fighting bundler cache permissions and a half-made symlink (vendor/bundle/bundle). It recovered, but a build packet for a Rails repo should pre-provision BUNDLE_PATH or the brief should state the exact bundle setup incantation.
  • Stray ~/.local directory in the repo root — an empty tree left by the bundler fight (a BUNDLE_USER_HOME mis-expansion). Harmless but real: workers escaping their worktree for writes, even trivially, is worth watching. Removed 2026-07-30.
  • .grokclaude/ was untracked and unignored — 1.5 MB of job artifacts (briefs, reports, scratch excerpts, a stale index.lock) sitting in git status. Now gitignored; the artifacts stay on disk as the run record.
  • Job lifecycle bookkeeping. The build job's meta.json still says needs_review; the commit is the de-facto close-out. Cosmetic, but it means blackboard state cannot be trusted as “what shipped”.

Should the workflow be the default, or selectable?

Recommendation Selectable by rule, not default by fiat. Encode the offload gate as a standing policy so the pipeline triggers on qualifying tasks without anyone typing /grokclaude — and never triggers on tasks where it can't pay.

Two runs of evidence say the pipeline pays on multi-feature builds and bulky research: this build kept ~6.8M tokens out of the host context for $3.36 and let the host spend its window on review and judgment rather than implementation. The same evidence says it should not be a blanket default:

  • Floor cost and latency are real. ~$3 and ~45 minutes wall for this shape. A one-file fix or a judgment call is faster and better done natively; the skill's own “say no when it doesn't pay” gate exists for a reason.
  • Host review is mandatory anyway. The pipeline shifts Claude's work from writing to reviewing; it does not remove it. Defaulting everything through grok would multiply review load without multiplying value on small tasks.
  • Brief-writing is a fixed cost. Workers share no context; tasks needing deep, hard-to-serialize repo context stay cheaper native.

Concretely, “selectable by rule” means a short standing policy in ~/.claude/CLAUDE.md: offload unprompted when a task is a self-contained build of roughly ≥2 features / ≥300 changed lines, or research over ≥~20–30K tokens of raw material — and say so in one line when doing it. Everything smaller stays native. The selection surfaces already exist (the /grokclaude skill, plus the grok-worker / grok-builder agent types callable from Workflow scripts); the only missing piece is the trigger rule.

Open follow-ups from the ship

  • devices.main_user_id backfill ran only because the install had one user at migrate time; when household users are added, each Kindle's main user must be set on its device page.
  • Writeback prefers the user's preferred Kindle only when that device has reading state for the book; otherwise it falls back to newest content_mtime across physical devices.
  • users ↔ devices circular nullable FKs (on_delete: :nullify) are fine for a household; revisit if per-user ACLs ever land (see the July review's parked multi-user items).
  • Pipeline side: pre-provision bundler in gc worktrees; put asset acquisition in briefs explicitly; close out job meta.json status when the host commits.
