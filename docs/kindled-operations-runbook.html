kindled operations runbook

Server (Folio) deploy

cd ~/traefik
docker compose build folio
docker compose up -d folio        # entrypoint runs db:prepare + seed
curl -s -o /dev/null -w "%{http_code}\n" https://kindle.scc.im/healthz

Source: ~/project/kindle-private-cloud/server. SQLite + storage live in /home/nik/folio/storage (bind mount). The Komga library is mounted read-only at /komga. Solid Queue runs inside Puma (SOLID_QUEUE_IN_PUMA=1) — one container.

Device access (SSH tunnel)

The Kindle opens a reverse SSH tunnel to this host (logs in as nik, binds 127.0.0.1:22222). It exists only while the device is awake and the tunnel session lives — expect it to come and go; re-activate from the device when needed.

ssh root@localhost -p 22222 -i ~/.ssh/id_ed25519x

If port 22222 refuses: check ss -tlnp | grep 22222 and journalctl -u sshd for the device's login; the device's WAN IP shows in folio's request logs. Port 2222 is Gitea — not the Kindle.

Daemon build + install

cd ~/project/kindle-private-cloud/kindled
./build-kindle.sh                                  # docker rust-musl-cross
scp -P 22222 -i ~/.ssh/id_ed25519x \
    target/armv7-unknown-linux-musleabihf/release/kindled \
    root@localhost:/mnt/us/privatecloud/kindled.new
ssh root@localhost -p 22222 -i ~/.ssh/id_ed25519x '
  cd /mnt/us/privatecloud
  stop kindled 2>/dev/null
  mv kindled.new kindled && chmod +x kindled
  start kindled'

Config: /mnt/us/privatecloud/config (KEY=VALUE: SERVER_URL, API_TOKEN, DOCUMENT_DIR, POLL_INTERVAL, AUTO_DOWNLOAD, THUMBNAIL_DIR, CLIPPINGS_PATH). State: state.json next to it. Logs: /mnt/us/privatecloud/kindled.log.

Boot persistence (upstart)

The daemon survives reboots via /etc/upstart/kindled.conf (repo copy: kindled/upstart/kindled.conf): starts on started lab126_gui, respawns on crash (verified live: kill -9 → new pid in ~3 s), backs off after 5 respawns/5 min.

mntroot rw
cp /mnt/us/privatecloud/upstart-kindled.conf /etc/upstart/kindled.conf
mntroot ro
start kindled; status kindled
Firmware OTA updates wipe /etc/upstart additions — reinstall the job after any Kindle system update. The KUAL Start/Stop entries delegate to upstart when the job exists, so the two supervisors never fight.

Health checks

# on the device
/mnt/us/privatecloud/kindled status   # config, storage, battery, tracked books, server health
/mnt/us/privatecloud/kindled sync     # one verbose pass
status kindled                        # upstart state

# on the server
docker exec folio bin/rails runner 'd=Device.last; puts d.last_sync_at, d.free_bytes'

The web device page (Devices → device) shows last sync, storage gauge, battery, firmware, sync history and the on-device library — all reported by the daemon's status POST each pass.

Troubleshooting

  • Books show text tiles / no covers — see the cover-tile findings artifact; delivery prep must produce joint MOBI with PDOC identity. Re-queue preparation by clearing prepared_source_sha256 and running PrepareKindleFileJob; the sha change re-delivers.
  • Row keeps stale metadata after re-delivery — expected if a file was replaced in place; the daemon's delete→rescan→write flow handles it. Manual fix: move the file away, wait for the row to drop, move it back.
  • Reading badge reset to 0% after re-delivery — cosmetic; the catalog row was recreated. Position lives in the .sdr and restores on open.
  • Scanner errors in /var/log/messages (scan_file_err … scan file failed) — normal during the delete-first replacement dance (file briefly absent).
  • Device page shows "never seen" — token mismatch or the daemon can't reach SERVER_URL; run kindled status on-device (prints server health).
  • SQLite "database busy" 503s to the daemon — the API replies Retry-After: 60 during bulk jobs; the daemon just polls again. No action needed.
