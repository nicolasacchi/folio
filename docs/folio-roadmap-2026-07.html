Folio — recommended roadmap

This sequences the full review into work you can actually schedule. Every item traces back to a verified finding. Ordering is value-for-effort with dependencies respected, not severity alone — a cheap fix that removes an existential risk beats an expensive one that polishes an edge.

Read this first. Folio is a single-user, self-hosted system that already works well. Nothing here is an emergency. But two facts dominate the ordering: there is no backup (one bad disk = total loss), and CI has never run (every change ships unguarded). Fix those two before anything else — they are each an afternoon, and they change the risk profile of every subsequent change. After that, the sequence de-risks authorization, then buys scale headroom, then hardens the daemon, then pays down UX debt, and finally opens the new directions that make Folio more than a Kindle pipeline.

P0 Safety net — do this week

Automated SQLite backup + a tested restore · effort S–M

The whole system state — catalog, reading history, annotations, delivery queues — lives in a handful of unreplicated files. Add Litestream (continuous streaming replication to a second disk or object store) or, minimally, an hourly sqlite3 .backup of each database to a separate volume, plus a one-command restore documented and actually run once in a drill. This is the highest-value item in the entire review.

Fixes: data #1 (critical, confirmed), testing/ops "no backup" (high, confirmed).

Make CI real: move it to the repo root and run RSpec · effort S

Move server/.github/workflows/ci.yml → .github/workflows/ (GitHub never looks under server/), and point it at rspec instead of the empty Minitest scaffold. Add the cargo build --target armv7 + cargo test step for kindled. Delete the vestigial server/test tree to end the dual-harness confusion. Now every push is guarded by the ~400 specs that already exist.

Fixes: testing/ops #1 and #2 (both critical, confirmed).

Deep health endpoint · effort S

Add a /healthz/deep that does a trivial SQLite write and checks a Solid Queue process heartbeat, so "container healthy" stops meaning "Puma booted" while conversions and deliveries are silently dead. Wire it to the compose healthcheck.

Fixes: testing/ops "healthchecks only prove Puma boots" (high, confirmed).

P1 Correctness & authorization

Scope the device API to deliveries (close the IDOR) · effort S

In find_book! (and the file/thumbnail/reading-state controllers), look the book up through current_device.deliveries instead of globally, so a token only reaches its own queued books. Update the specs that currently assert unscoped download. Small change, removes the "one leaked token = whole library" property — especially valuable given tokens sit in plaintext on the Kindle's FAT partition.

Fixes: security #1 (high, confirmed, hand-verified).

Stuck-conversion sweeper + fix cancel_queued · effort S

A recurring job that resets running conversions with no live Solid Queue job back to a re-queueable state, and make cancel_queued also clear running rows. Without this, one cancelled-mid-run conversion blocks that book from ever converting again.

Fixes: data #3 (high, confirmed, hand-verified).

Unique constraint on active conversions · effort M

Add a partial unique index on (book_id, target_format) over active statuses so the check-then-create! race can't produce duplicate Calibre runs. Audit for existing dupes first.

Fixes: rails #1 (high, confirmed).

Prepared-copy destroy hook + orphan GC · effort M

Add an after_destroy that removes the prepared variant when a single book_file is destroyed, plus a recurring sweep that reconciles prepared_files/ and covers against the DB. Stops unbounded disk growth.

Fixes: data #5 (high, confirmed) + rails prepared-cleanup (medium).

Token & session hardening bundle · effort S–M
  • Hash device tokens at rest (look up by SHA-256; show the plaintext once on creation, in a copy/QR affordance, not a flash line).
  • Add a session lifetime and revoke sessions on any password change (admin-initiated included).
  • Rate-limit /api/v1 (Rack::Attack or a Traefik middleware) — cap body sizes and request rate.
  • SMTP verify-peer on; pin an enrichment redirect allowlist.

Fixes: security #2, #3, #5, SMTP, SSRF-class (all confirmed/medium).

Cheap model-integrity guards · effort S

Add the annotations.source inclusion validation, consolidate the two divergent conversion-source-preference constants into one, and wrap FTS index_book! in an IMMEDIATE transaction. Three small edits that each close a latent inconsistency.

Fixes: rails #4, #5; data FTS-transaction (medium, confirmed).

P2 Scale headroom — before the library gets big

Materialise catalog aggregates · effort M

The Catalog page's 1-minute-cached aggregates scan multi-GB FTS content and full-table pluck+group_by on every miss. Add a books.has_fulltext boolean (maintained by the index job) and counter caches for the dashboard numbers, so the page reads cheap indexed columns instead of scanning.

Fixes: data #2 (high, confirmed, hand-verified).

Queue discipline for bulk work · effort S–M

Move IndexBookJob (and other bulk jobs) off :default onto a dedicated low-priority queue; serialise Calibre work onto a single-concurrency conversion queue; add limits_concurrency/unique-job guards to PrepareKindleFileJob so the manifest self-heal can't enqueue duplicates. Keeps bulk work from starving the device API's write lock.

Fixes: data #4 (high), manifest self-heal (medium), Calibre serialisation.

Targeted indexes + WAL/integrity recurring job · effort S–M

Add covering indexes matched to the real hot queries (enrichment candidates, delivery lookups, annotation matching), and a recurring job that runs PRAGMA wal_checkpoint(TRUNCATE) and integrity_check so WAL growth and silent corruption surface early.

Fixes: data "missing indexes" (medium), plus operational hygiene.

Option: split Solid Queue out of Puma · effort S (deploy)

When bulk jobs start contending with requests, run the existing bin/jobs as a sidecar container and unset SOLID_QUEUE_IN_PUMA. No code change — just compose. Keep this in the back pocket as the pressure valve.

Addresses: data "Solid Queue + Puma contention" (medium). Already supported in-repo.

P3 Daemon resilience & UX debt

kindled (Rust)

Path containment on every manifest-derived join · effort S

Canonicalise item.filename, thumbnail.filename and removal paths and reject anything that escapes the base directory (absolute paths, ../). Defense-in-depth against a buggy/compromised server writing outside PrivateCloud.

Fixes: kindled #1, #4 (high, confirmed, hand-verified).

Retry backoff, download resume, atomic SDR unpack, state backup chain · effort M–L
  • Exponential backoff on API calls (don't waste a poll on a flaky network).
  • HTTP Range resume on the .part file for interrupted downloads + a statvfs precheck.
  • Unpack .sdr into a temp dir, validate, atomic swap.
  • Keep a backup chain for state.json and log loudly on parse failure instead of silently resetting.
  • Add crash/restart telemetry so an upstart restart-storm is visible server-side.

Fixes: kindled #2, #3, SDR, state-corruption, disk-full (confirmed/medium–high).

Web UX

Communicate long operations and failures · effort M
  • Expose the full conversion log in a modal/drawer (stop truncating to a fragment).
  • Reader "preparing" state: progress indicator + timeout/fallback message.
  • Surface failed-conversion badges on the library shelf, not just the detail page.
  • Make "Keep Reading" persist across filters.
  • Add screen-reader announcements for search-mode state (a11y).

Fixes: UX #1, #2 (critical), #3, #4, #5 (high) — all confirmed.

Second-tier UX polish · effort M

Eviction-reason tooltips with criteria; duplicates page sort/filter + merge conflict preview; per-job progress on batch operations; preserve reader position across paginated↔scrolled; a cover-grid series index; document the annotation location unit. Batch as a "reading-app polish" sprint.

Fixes: the medium/low UX register.

P4 New directions — the ideas worth building

These are the genuinely new capabilities (each verified as not already in the repo). Ordered by strategic value for the effort. They turn Folio from "my Kindle's private backend" into "the hub for how I read."

1. OPDS 1.2 / 2.0 catalog · effort M

A read-only OPDS feed (with acquisition links reusing the existing download endpoints) instantly makes Folio's whole library browsable and pullable from KOReader, Marvin, Thorium, Panels, and Calibre — without building a client for each. The single highest reach-per-effort feature available. Auth via HTTP Basic or a scoped token.

From: ecosystem #1 (high, confirmed). Prereq: a token/basic-auth scheme for OPDS clients.

2. KOReader progress-sync (kosync) server · effort M

Folio already has the hard part — a two-way position model and merge logic. Exposing the small, documented kosync HTTP API makes Folio the self-hosted progress-sync server for KOReader across all a user's devices, a direct extension of what it does for the Kindle. Pairs naturally with OPDS (browse from KOReader, sync back to Folio).

From: ecosystem #2 (high, confirmed). Prereq: map kosync's document-hash keying onto reader_positions.

3. Deep semantic search: chunked fulltext embeddings + hybrid ranking · effort M

Today's embeddings cover only book-level metadata, so "semantic search" can't find a concept inside a book. Chunk the fulltext Folio already extracts, embed the chunks (the informers + sqlite-vec stack is in place), and blend vector hits with the existing BM25 FTS for true hybrid search. Turns a shallow feature into a real one using ingredients that already exist.

From: ecosystem #3 (medium, confirmed). Prereq: chunking + a vectors-per-chunk table.

4. Smart shelves (rule-based collections) + per-book vocab notebook · effort M / S

Saved rules (by author, tag, year, read-state, "has highlights") that materialise as dynamic shelves — a big browsing win at scale and a natural home for the taxonomy work already started. And a per-book vocabulary notebook that captures the dictionary lookups the reader already makes (the offline en/it dictionary is built) into an exportable study list.

From: ecosystem smart-shelves + vocab-notebook (confirmed new). Prereq: persist lookups; a rules DSL.

5. Local-LLM layer: RAG over highlights + book/chapter summaries · effort L

With chunked embeddings (item 3) in place, an optional local LLM (e.g. Ollama) can answer questions over a user's own highlights and notes, and generate chapter/book summaries on demand. Privacy-preserving by construction — everything stays on the self-hosted box, matching Folio's whole ethos. Gate it behind an opt-in so the base system stays dependency-light.

From: ecosystem RAG + summaries (confirmed new). Prereq: item 3; an optional local-LLM adapter.

6. Deeper Komga bridge, more enrich providers, social scrobble · effort S–L

Longer-horizon adjacencies: a two-way read-progress bridge to the Komga library Folio already mounts (API-level, not just files); a Hardcover/ISBNdb enrichment provider for better metadata coverage; an optional Bookwyrm scrobble for reading status. Each is independent and low-commitment; pick by appetite.

From: ecosystem Komga/enrich/Bookwyrm (confirmed new).

Deliberately parked: a Kobo Sync subset (XL, only if a Kobo enters the picture) and multi-user library ACLs (real work, only worth it if Folio goes beyond a family). Both are noted in the review; neither pays off yet.

Suggested first cut

If you want a concrete two-week slice: all of P0 (backup + CI + deep health — an afternoon or two), then the P1 device-API scoping, the stuck-conversion sweeper, and the token/session hardening bundle. That removes the only existential risk (no backup), makes every future change safe to ship (CI), closes the widest authorization gap, and kills the most annoying confirmed bug — for a few days of work. Everything after that is genuine improvement on an already-healthy system, and the P4 directions are where Folio gets more interesting: OPDS and KOReader sync first, then the semantic-search-over-highlights line that its existing embedding stack is already reaching toward.
